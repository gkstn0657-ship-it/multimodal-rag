# 비용 분석: 로컬 VLM vs 상용 API

> Phase 5 산출물. 이 프로젝트를 상용 API로 했다면 얼마가 들었을지, 로컬 운영과의 손익분기가 어디인지,
> 그리고 왜 비용과 무관하게 로컬을 택했는지를 적는다. 모든 숫자는 아래 파라미터 표에서 나오며,
> 파라미터를 바꾸면 결과도 그대로 따라간다.

## 3. 상용 API로 했을 때 (Claude Sonnet 5 기준)

### 3-1. 인덱싱 (1회)

캡셔닝 대상만 API로 보낼 때 (우리 라우팅 그대로, 997장):

| 항목 | 계산 | 토큰 | 비용 |
|---|---|---|---|
| 입력 | 997 × (1,545 + 150) | 1.69M | $3.38 |
| 출력 | 997 × 200 | 0.20M | $1.99 |
| **합계** | | | **$5.37 ≈ 7,400원** |

라우팅 없이 40,781장 전부 캡셔닝했다면: 입력 69.1M ($138), 출력 8.2M ($82) → **$220 ≈ 303,000원**.
라우팅(D-04)이 API 비용을 41분의 1로 줄인다는 뜻이다. 로컬에서는 시간을 12시간→1시간으로 줄인 같은 결정이다.

Opus 5로 하면 위 금액의 2.5배, Haiku 4.5로 하면 0.5배.

### 3-2. 질의 (월간, 반복)

질의 1건 = 입력 2,850 + 출력 300 토큰 → Sonnet 5 기준 $0.0057 + $0.0030 = **$0.0087 ≈ 12원**.
이미지가 붙는 질의(전체의 약 20%, 15문항 중 3문항)는 이미지 1장당 약 1,545토큰이 더해져 약 $0.012.

| 월 질의 Q | API 비용/월 |
|---|---|
| 1,000 | $8.7 ≈ 12,000원 |
| 10,000 | $87 ≈ 120,000원 |
| 50,000 | $435 ≈ 600,000원 |

프롬프트 캐싱(시스템 프롬프트·청크 재사용)이나 배치 API를 쓰면 입력 비용을 더 낮출 수 있지만, 여기서는 정가로 둔다.

## 4. 로컬 운영 비용

### 4-1. 전기

| 항목 | 계산 | 월 비용 |
|---|---|---|
| 인덱싱 1회 | 1.5h × 150W = 0.225kWh | 45원 (1회성) |
| 질의 처리 | Q × 20초 × 150W → Q=10,000이면 8.3kWh | 1,700원 |
| 24시간 대기 | 30W × 720h = 21.6kWh | 4,320원 |
| **합계 (Q=10,000)** | | **약 6,000원/월** |

전기는 사실상 무시할 수 있는 수준이다. 로컬 비용의 본체는 하드웨어다.

### 4-2. 하드웨어 상각

2,500,000원 / 36개월 = **69,444원/월**. 이 장비를 이 서비스 전용으로 본다는 가정이다.
개발자 노트북을 겸용하면 귀속 비율만큼 줄고, 이미 있는 장비면 0이다.

### 4-3. 로컬 합계

| 월 질의 Q | 전기 | 하드웨어 | 로컬 합계/월 |
|---|---|---|---|
| 1,000 | 4,500원 | 69,444원 | 약 74,000원 |
| 10,000 | 6,000원 | 69,444원 | 약 75,500원 |
| 50,000 | 12,800원 | 69,444원 | 약 82,000원 |

## 5. 손익분기

| 월 질의 Q | API (Sonnet 5) | 로컬 (상각 포함) | 유리한 쪽 |
|---|---|---|---|
| 1,000 | 12,000원 | 74,000원 | API |
| 6,300 | 76,000원 | 75,000원 | **분기점** |
| 10,000 | 120,000원 | 75,500원 | 로컬 |
| 50,000 | 600,000원 | 82,000원 | 로컬 |

**순수 비용만 보면 월 약 6,300건 아래에서는 API가 싸다.** 하드웨어를 이미 갖고 있다면(상각 0) 로컬은 월 6,000원이라
어느 규모에서도 로컬이 싸다. 하드웨어 상각을 어떻게 잡느냐가 결론을 뒤집는 유일한 변수다.

## 6. 왜 로컬인가 — 비용이 아닌 이유

이 프로젝트의 로컬 선택은 손익분기 계산에서 나온 게 아니다. 두 축이다.

1. **보안 (문서 반출 불가).** 코퍼스는 공공기관 보고서지만, 이 파이프라인이 겨냥하는 현장은 금융·공공·사내
   문서다. 페이지 이미지를 외부 API로 보내는 것 자체가 허용되지 않는 환경이 많다. 이 경우 API 옵션은 비용이
   0원이어도 선택지가 아니다. 로컬 VLM은 이 제약을 만족하는 유일한 구조다.
2. **비용 상한의 예측 가능성.** API는 질의량에 정비례한다. 로컬은 하드웨어 한 대의 고정비 안에서 처리량 상한까지
   비용이 평평하다. 위 표에서 Q가 10배 늘 때 API는 10배, 로컬은 1.1배다.

대가는 셋이다. (a) 8GB VRAM에 맞추느라 7B 모델·4k 컨텍스트·이미지 2장 제한을 감수했다(D-02). 상용 API의
최상위 모델보다 답변 품질이 낮다. (b) 처리량 상한이 있다 — 답변 15~25초, 동시 4요청 포화. (c) 운영 부담이
있다 — 러너 손상(D-12), 컨텍스트 초과(D-09) 같은 문제를 직접 잡아야 했다.

## 7. 재계산 방법

```
API 인덱싱   = 페이지수 × (이미지토큰 + 150) × P_in + 페이지수 × 200 × P_out
API 질의/월  = Q × (2,850 × P_in + 300 × P_out)
로컬 전기/월 = (Q × 20s × 150W + 720h × 30W) × 전기요금
로컬 합계/월 = 로컬 전기 + 하드웨어가격 / 상각월수
```

전기요금과 하드웨어 상각은 가정값이다. 실제 계약 전력 단가와 장비 귀속 비율을 넣어 다시 계산할 것.
