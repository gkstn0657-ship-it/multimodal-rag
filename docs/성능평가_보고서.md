# 멀티모달 RAG 성능평가 보고서

## 개요

텍스트·스캔·표·차트가 섞인 문서(SDS KoPub VDR 40,781페이지, DART 공시 8,418페이지)를 대상으로 검색·생성 파이프라인을 구축하고 평가했습니다. 텍스트 레이어가 있는 페이지는 텍스트 그대로, 텍스트가 빈약한 페이지는 VLM(Qwen2.5-VL) 캡셔닝을 거쳐 인덱싱했고, 검색은 BGE-M3 밀집 임베딩과 BM25를 RRF로 결합한 하이브리드 방식을 씁니다.

## 파이프라인 최종 구성

```
문서 → 페이지 라우팅(TEXT/OCR/IMAGE/BLANK)
     → IMAGE 경로만 VLM 전사 캡션(v3) + OCR 합집합
     → BGE-M3 임베딩 + BM25(문서명·회사·사업연도 접두어 포함) 색인
     → 질의: 밀집 top-10 + BM25 top-10을 RRF로 병합
     → bge-reranker-v2-m3 재랭킹 → 상위 5개
     → VLM 답변 생성(상위 2개 청크는 원본 이미지 직접 투입)
```

여기까지 오는 동안 세 번 방향을 크게 틀었습니다. 캡션 프롬프트는 창작을 막다가(v2) 검색 신호가 너무 짧아져(v3에서 전사 우선으로 재작성) 다시 손봤고, 검색은 밀집 단독으로 시작했다가 회사명·연도 같은 고유명사가 안 잡히는 문제로 BM25를 얹었고, 그래도 남은 문제를 메타데이터 접두어로 보완했습니다.

## 검색 성능

### SDS KoPub 라벨셋 (600문항, 자동 채점)

| 지표 | 값 |
|---|---|
| Recall@1 | 0.448 |
| Recall@5 | 0.763 |
| Recall@10 | 0.852 |
| MRR | 0.579 |
| nDCG@5 | 0.616 |

라벨셋은 정답 페이지의 99.8%가 TEXT 경로라, 이 지표는 사실상 "일반 텍스트 RAG로서 얼마나 잘 되는가"를 봅니다. 하이브리드 검색을 넣기 전(밀집 단독)에는 전체 Recall@1이 0.413이었는데, 하이브리드 적용 후 0.448로 올랐습니다.

### 합성 질의 (IMAGE 경로 194건에서 자체 생성, 자동 채점)

라벨셋으로는 캡셔닝 효과를 검증할 수 없어(정답이 IMAGE 경로인 문항이 1개뿐) 직접 만든 질의셋입니다.

| 구성 | Recall@5 | MRR | nDCG@5 |
|---|---|---|---|
| v2 캡션(창작 방지, 짧음) | 0.470 | 0.355 | 0.376 |
| v3 캡션+OCR, 밀집 단독 | 0.524 | 0.402 | 0.425 |
| **v3 캡션+OCR, 하이브리드+접두어(최종)** | **0.681** | **0.502** | **0.543** |

v2에서 v3로 캡션 방식을 바꾼 것보다 하이브리드 검색을 얹은 효과가 더 컸습니다. 정보를 더 정확히 옮기는 것보다, 옮긴 정보를 정확히 찾아내는 쪽이 병목이었다는 뜻입니다.

### 사람이 실제로 물을 법한 질의 (42문항, LLM 판정)

자동 지표 두 개가 서로 다른 방향으로 편향돼 있어(라벨셋은 텍스트 쪽에, 합성셋은 캡션 어휘 쪽에 유리) 별도로 검증했습니다. 판정은 생성 모델과 다른 계열(Claude)이 검색 결과 페이지 하나하나에 정답/부분/무관 등급을 매기는 방식으로 진행했습니다.

| 유형 | 문항 수 | nDCG@5 | Recall@5(정답 등급) | 무관 비율 |
|---|---|---|---|---|
| 텍스트 | 5 | 0.910 | 1.00 | 0.12 |
| 표·차트(visual) | 5 | 0.974 | 0.80 | 0.24 |
| 복합(cross) | 5 | 0.931 | 1.00 | 0.08 |
| **IMAGE 경로** | 15 | 0.890 | **0.27** | 0.40 |

IMAGE 경로가 가장 약합니다. 원인을 뜯어보니 검색 자체는 나쁘지 않았습니다 — 정답 페이지를 80%는 찾았습니다. 문제는 그 페이지 다수가 장 구분지·표지처럼 원래 담긴 정보가 없는 페이지였다는 점입니다. 캡셔닝을 아무리 잘해도 없는 정보를 만들어낼 수는 없으니, 이건 캡션 품질 문제가 아니라 이 방식(이미지를 텍스트로 바꿔 검색하는 방식) 자체의 구조적 한계로 봅니다.

### DART 공시 문서 (10문항, 실사용형 질의, LLM 판정)

회사명·사업연도가 뒤섞인 실제 기업 공시 문서로 별도 검증했습니다.

| 구성 | Recall@5(정답 등급) | 무관 비율 |
|---|---|---|
| 밀집 단독 | 0.30 | 0.62 |
| + 하이브리드 | 0.40 | 0.62 |
| + 문서명·회사·사업연도 접두어 | **0.50** | 0.62 |

접두어까지 넣어 목표(0.50)를 달성했지만, 무관 비율은 세 조합 모두 0.62로 그대로입니다. "LG화학을 물었는데 NAVER 페이지가 나온다" 같은 회사 불일치는 접두어로 줄었지만, "같은 회사의 다른 주제 페이지가 딸려온다" 같은 문서 내부 혼동은 남아 있습니다. 검색 단계 신호(리랭크 점수, 점수 격차, 후보 다양성)로 이걸 걸러내는 기권 게이트를 시도했으나, 세 신호 모두 정답과 오답을 깨끗이 가르지 못해 채택하지 않았습니다.

## 생성 성능

15문항(text 5·cross 5·visual 5)을 두 조건으로 채점했습니다. ours는 원본 페이지 이미지를 VLM에 직접 투입하고, baseline은 텍스트(캡션 포함)만 씁니다. 채점은 정확성·완전성·출처정확도·간결성 100점 배점으로, 생성 모델과 다른 계열의 채점자가 맡았습니다.

| 유형 | ours | baseline | 차이 |
|---|---|---|---|
| 전체 | 64.6 | 62.5 | +2.1 |
| **표·차트(visual)** | **66.2** | **54.8** | **+11.4** |
| text | 62.4 | 66.6 | -4.2 |
| cross | 65.2 | 66.0 | -0.8 |

이미지 투입 효과는 표·차트 질문에서만 뚜렷하게 나타났습니다. 텍스트 질문에서는 애초에 투입할 이미지가 없어 두 조건이 사실상 같은 답을 냈고, 남은 차이는 temperature 0에서도 완전히 사라지지 않는 생성 변동성으로 봅니다. 설계 의도(이미지가 필요한 곳에서만 이미지가 도움된다)와 정확히 맞아떨어지는 결과입니다.

채점 과정에서 부작용 하나를 발견했습니다. 답변 뒤에 자기모순적으로 기권 문구가 붙는 문제(과거에 한 번 고쳤던 것)가 특정 조건(기권 문구가 실제 답과 같은 문장에 붙는 경우)에서 재현됐습니다. 원인은 문구 제거 로직이 줄 단위로만 동작해서, 실제 답과 기권 문구가 한 줄에 있으면 그 줄 전체가 지워져 버리는 것이었습니다. 문장 단위로 고치고 회귀 테스트를 추가했습니다.

## 남은 한계

- IMAGE 경로 페이지 다수가 정보량이 적은 구분지·표지라, 캡셔닝 방식 자체의 상한이 낮습니다. 이미지를 직접 임베딩하는 방식(ColPali·ColQwen2류)과 정면 비교하면 이 손실의 크기를 수치로 확인할 수 있는데, 아직 하지 않았습니다.
- DART 문서 내부의 "같은 회사, 다른 주제" 혼동은 검색 단계에서 못 잡았고, 검색 실패 시 답변을 내지 말아야 하는 기권 게이트도 아직 없습니다.
- 판정은 42문항, 생성 채점은 15문항으로 표본이 작습니다. 방향은 뚜렷하지만 절대 수치의 신뢰구간은 넓게 봐야 합니다.
