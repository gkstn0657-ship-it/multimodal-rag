# 멀티모달 RAG 프로젝트 — Claude Code 실행 계획

> 사용법: 각 Phase의 프롬프트를 순서대로 Claude Code에 붙여넣는다.
> 한 Phase의 검증 기준을 통과한 뒤에만 다음 Phase로 넘어간다.
> 환경: RTX 4070 (12GB), Python 3.11+, VSCode Claude Code 확장

---

## Phase 0 — 환경 구축 및 VLM 서빙 확인

**프롬프트:**
```
RTX 4070(12GB) 환경에서 멀티모달 RAG 프로젝트를 시작한다.

1. 프로젝트 구조를 잡아줘: multimodal-rag/ 아래 servers/, indexing/, eval/, data/
2. vLLM을 설치하고 Qwen2.5-VL-7B-Instruct-AWQ를 서빙하는 스크립트를 만들어줘.
   - --max-model-len 8192, --gpu-memory-utilization 0.9
   - OpenAI 호환 API로 띄우고, 이미지 입력이 되는지 테스트하는 스크립트 포함
3. 테스트: 샘플 이미지 1장을 보내서 한국어 설명이 돌아오는지 확인하는
   test_vlm.py를 만들어서 실행해줘.

주의: pip 설치 시 CUDA 버전 호환을 먼저 확인하고 진행해.
```

**검증 기준:** test_vlm.py가 이미지에 대한 한국어 응답을 출력하면 통과.
**실패 시:** VRAM 부족이면 --max-model-len 4096으로 낮춰 재시도.

## Phase 1 — 캡셔닝 인덱싱 파이프라인

**프롬프트:**
```
Phase 0에서 띄운 Qwen2.5-VL 서버를 사용해 문서 인덱싱 파이프라인을 만들어줘.

1. PDF 입력 처리 (indexing/ingest.py):
   - 텍스트 레이어가 있는 페이지 → 기존 텍스트 추출 (pymupdf)
   - 텍스트가 없거나 빈약한 페이지(스캔본/이미지) → 페이지를 이미지로
     렌더링 후 VLM 캡셔닝으로 라우팅
   - 라우팅 기준: 페이지당 추출 텍스트 100자 미만이면 이미지 경로로
2. 캡셔닝 프롬프트 (indexing/caption.py):
   - "이 문서 페이지의 내용을 한국어로 설명하라. 표는 행·열 구조를 유지해
     마크다운으로, 차트는 축·수치·추세를 구체적으로 기술하라"
   - 결과에 원본 페이지 번호·파일명 메타데이터 부착
3. 임베딩·저장:
   - BGE-M3로 임베딩, ChromaDB에 저장
   - 캡션 텍스트와 원본 페이지 이미지 경로를 함께 메타데이터로 저장
     (답변 단계에서 원본 이미지를 다시 쓰기 위함)
4. 테스트: data/에 샘플 PDF를 넣고 전체 인덱싱을 실행, 저장된 청크
   수와 라우팅 통계(텍스트 경로 n건 / 이미지 경로 n건)를 출력해줘.
```

**검증 기준:** 스캔 페이지가 이미지 경로로 라우팅되고 캡션이 저장되면 통과.
**실패 시:** 캡션 품질이 낮으면 캡셔닝 프롬프트만 수정 (파이프라인 건드리지 말 것).

## Phase 2 — 검색 + VLM 답변 생성

**프롬프트:**
```
검색과 답변 생성을 구현해줘.

1. 검색 (servers/retrieve.py):
   - 질문을 BGE-M3로 임베딩 → ChromaDB 코사인 유사도 top-10
   - bge-reranker-v2-m3로 재랭킹 → top-5 사용
2. 답변 생성 (servers/answer.py):
   - 검색된 청크가 이미지 경로 출신이면: 캡션이 아니라 **원본 페이지
     이미지**를 VLM에 직접 입력
   - 텍스트 출신이면: 텍스트를 컨텍스트로 입력
   - 시스템 프롬프트: "제공된 문서에 근거해서만 답하라. 근거가 없으면
     '문서에서 찾을 수 없습니다'라고 답하라. 답변 끝에 출처(파일명·페이지)를
     표기하라"
3. FastAPI 엔드포인트 (servers/main.py): POST /ask {"question": ...}
4. 테스트: 텍스트 질문 1개 + 표/차트 질문 1개를 던져 출처가 붙은
   답변이 나오는지 확인해줘.
```

**검증 기준:** 표/차트 질문에서 원본 이미지 기반 답변 + 출처 표기가 되면 통과.

## Phase 3 — 평가

**프롬프트:**
```
평가 체계를 구축해줘. 기존 프로젝트의 평가 방법론을 따른다.

1. 평가셋 (eval/questions.json):
   - 텍스트 문서 질문 8개 (기존 프로젝트 8문항 재사용)
   - 이미지/스캔 문서 질문 5개
   - 표 질문 3개, 차트 질문 2개
   - 각 질문에 정답 근거(파일·페이지) 명시
2. 채점 (eval/judge.py):
   - 기준: 정확성(40) + 완전성(25) + 출처정확도(20) + 간결성(15)
   - 로컬 VLM을 judge로 사용하되, 판정 캐시를 저장해 재실행 시 재사용
3. 비교 실험:
   - baseline: 텍스트 추출만 (이미지 페이지 제외)
   - ours: 캡셔닝 라우팅 포함
   - 두 조건의 점수를 표로 출력하고 eval/report.json에 저장해줘.
```

**검증 기준:** 이미지 질문에서 baseline 대비 개선이 수치로 나오면 통과.
**주의:** 채점 루브릭은 실행 전에 확정하고, 결과 보고 바꾸지 말 것 (사전등록 원칙).

## Phase 4 (선택) — ColPali 비교

**프롬프트:**
```
ColPali(colpali-engine, vidore/colqwen2.5 계열)를 추가해 캡셔닝 방식과
비교 실험을 해줘.

1. indexing/colpali_index.py: 페이지 이미지를 ColQwen으로 멀티벡터
   임베딩, 별도 인덱스에 저장 (Qdrant 권장 — ChromaDB는 멀티벡터 미지원)
2. 동일한 평가셋으로 캡셔닝 vs ColPali 검색 성능 비교
3. 저장 용량·인덱싱 시간·검색 지연도 함께 측정해 트레이드오프 표 작성
```

**검증 기준:** 성능 + 비용 트레이드오프 표가 나오면 통과. 시간 없으면 이 Phase는 생략.

## Phase 5 — 채용 어필 요소 (운영·비용·보안 관점)

**프롬프트:**
```
프로덕션 관점의 마무리 작업을 해줘.

1. 지연시간 계측 (servers/metrics.py):
   - /ask 요청마다 단계별 소요시간 로깅: 검색 / 리랭킹 / VLM 생성
   - 평가 실행 시 p50·p95 지연시간을 report.json에 포함
2. 비용 분석 문서 (docs/cost_analysis.md):
   - 이 프로젝트를 GPT-4o API로 했을 때 예상 비용 계산
     (인덱싱 페이지 수 × 캡셔닝 토큰 + 월 질의량 가정 × 답변 토큰)
   - 로컬 4070 운영과의 손익분기점 제시
   - "왜 로컬인가"를 보안(문서 반출 불가) + 비용 두 축으로 정리
3. 실패 처리:
   - VLM 서버 다운 시 503 + 명확한 에러 메시지
   - 검색 결과 0건 시 "문서에서 찾을 수 없습니다" 정상 응답
4. README에 아키텍처 다이어그램(mermaid)과 위 내용 요약 추가
```

**검증 기준:** report.json에 지연시간이 포함되고 cost_analysis.md가 완성되면 통과.

**왜 이 Phase가 채용에 중요한가:**
- 신입 포트폴리오 대부분이 "만들었다"에서 끝남. **지연시간·비용·장애 처리**를
  다룬 순간 "운영을 생각해본 사람"으로 분류됨
- "보안 때문에 로컬 선택"은 금융·공공·대기업 사내 챗봇의 실제 요구사항 —
  면접에서 현업 시나리오 이해도로 직결
- 비용 손익분기 분석은 "기술 선택에 근거를 대는 사람"이라는 신호

## Claude Code 권한/운영 참고

- **허용해도 되는 것:** 프로젝트 폴더 내 파일 생성·수정, pip install, 로컬 서버 실행
- **매번 확인할 것:** 프로젝트 폴더 밖 파일 수정, rm 계열 삭제 명령
- vLLM 서버는 Claude Code가 백그라운드로 띄우면 관리가 꼬이기 쉬움 →
  **서버는 별도 터미널에서 직접 실행**하고, Claude Code에는 "서버가
  localhost:8000에 떠 있다"고 알려주는 방식 권장
- 한 Phase가 끝나면 git commit 요청하기 ("여기까지 커밋해줘") —
  다음 Phase에서 망가져도 되돌릴 수 있게
- 긴 인덱싱 작업은 Claude Code 대화가 아니라 스크립트로 만들어 직접 실행
  (대화 타임아웃 방지)
