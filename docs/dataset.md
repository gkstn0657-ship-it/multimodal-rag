## 1차: SDS KoPub VDR

- 출처: Samsung SDS Research, arXiv 2511.04910 (2025-11). HuggingFace `SamsungSDS-Research/SDS-KoPub-VDR-Benchmark`.
- 내용: 한국 공공문서 361건. 256건은 공공누리 1유형(KOGL Type 1), 105건은 법령 포털.
  표·차트·다단 레이아웃 포함. 질의는 텍스트 기반 / 시각 기반 / 교차모달 세 범주로 분류됨.
- 라벨: 질의-페이지-정답 600쌍. GPT-4o 초안 생성 후 사람 검증.
- 선정 이유:
  1. 한국어이면서 4만 페이지 규모의 유일한 공개 문서 검색 벤치마크.
  2. 공공누리 1유형이라 코퍼스와 결과를 GitHub 레포에 재배포 가능.
  3. 검색 정답 라벨이 있어 논문 baseline(ColPali 계열 등)과 nDCG를 직접 비교할 수 있음.
  4. 공공·법률 문서는 "보안 때문에 로컬"이라는 이 프로젝트의 서빙 시나리오와 정확히 맞음.
  5. 질의 범주(텍스트/시각/교차모달)가 이미 층화돼 있어 평가 설계에 그대로 승계 가능.

## 2차: DART 공시 문서

- 출처: 금융감독원 OpenDART API (인증키 발급 필요, 일일 호출 한도 존재. 2026-05 기준 20,000건으로 알려짐, 이용약관에서 재확인).
  `OpenDartReader` 파이썬 라이브러리로 첨부파일 목록·다운로드 가능.
- 대상: 상장사 사업보고서 본문과 첨부(감사보고서·정관 등), 지속가능경영보고서.
- 선정 이유:
  1. 실제 기업이 생산·소비하는 문서. 표 밀도가 매우 높고 차트가 많음.
  2. 같은 회사의 여러 연도 보고서가 서로 강한 방해 문서(near-duplicate)로 작동함.
     "2024년 기준"처럼 연도가 붙은 질의에서 메타데이터 필터의 필요성을 드러냄.
  3. 오래된 첨부에 스캔본이 섞여 있어 텍스트/이미지 라우팅이 실제로 발동함.
- 주의: 라벨이 없으므로 평가셋은 직접 만든다. 사전등록 원칙을 여기서 적용한다.

## 검토했으나 제외한 후보

| 후보 | 제외 이유 |
|---|---|
| AI Hub 금융업 특화 문서 OCR (50,000장) | 내국인 한정·재배포 금지라 공개 레포에 넣을 수 없음. 고객 작성 양식이라 개인정보 리스크. QA 라벨이 아니라 OCR 박스 라벨. |
| ViDoRe V3 (26k 페이지) | 한국어 미포함(영·불·서·독·이·포). 인쇄 문서 위주로 스캔이 없음. |
| KRETA / KOFFVQA | 단일 이미지 VQA라 문서 검색 코퍼스가 아님. 캡셔닝 품질 점검용으로는 참고 가능. |
| M3DocVQA (40k 페이지) | 위키피디아 PDF라 기업 문서 현실감이 낮음. |

## 선정 시 함께 고려한 항목 (심사자 관점)

1. **라이선스와 재배포.** 포트폴리오는 공개 레포다. 공공누리 1유형(SDS KoPub, DART 공시)은 가능, AI Hub는 불가, UniDoc-Bench는 CC-BY-NC로 비상업 조건.
2. **재현 가능성.** PDF 원본은 레포에 넣지 않는다. `data/manifest.jsonl`(URL·해시·수집일)과 `scripts/fetch_corpus.py`만 커밋해 누구든 같은 코퍼스를 다시 받을 수 있게 한다.
3. **스캔 비율을 측정한다.** 라우팅이 실제로 동작하는지 보이려면 코퍼스에서 텍스트 레이어 없는 페이지가 몇 %인지 먼저 재고 보고서에 적는다. 부족하면 DART 구형 첨부를 추가한다.
4. **연산 예산으로 규모를 정한다.** RTX 4070 Laptop 8GB에서 7B VLM 캡셔닝은 페이지당 수 초에서 수십 초다. Phase 0에서 페이지/시간을 측정하고, 이미지 경로로 갈 페이지 수 상한(예: 3,000~5,000)을 정한 뒤 코퍼스 슬라이스를 확정한다. 텍스트 경로 페이지는 비용이 거의 없어 4만 페이지 전체를 인덱싱해도 된다.
5. **개인정보.** 공개 공시·공공문서만 쓴다. 고객 작성 양식류는 배제한다.
6. **모델 암기 누출.** 공개 문서는 VLM 사전학습에 포함됐을 수 있다. 평가 질의는 가급적 2025년 이후 문서에서 뽑고, 이 한계를 보고서에 명시한다.
7. **라벨 있는 셋과 없는 셋을 함께 쓴다.** SDS KoPub으로 공개 baseline과 비교해 신뢰를 확보하고, DART로 "현업 직원이 실제로 물을" 제품형 질의를 평가한다.
8. **방해 문서 설계.** 동일 회사 다년도, 동일 양식 다회사 문서를 의도적으로 포함해 검색기가 표면 유사도가 아니라 내용으로 구분하는지 본다.
9. **언어 혼재.** 한국어 문서 안에 영문 표·약어가 섞인다. BGE-M3가 다국어라 문제없지만, 캡셔닝 프롬프트가 영문 표 헤더를 한국어로 임의 번역하지 않도록 지시한다.
10. **숫자 충실도.** 표 중심 문서에서 캡셔닝의 최대 위험은 숫자 오기다. 캡션 단계에서 숫자 일치율을 별도 측정한다.
